1. Ringkasan sistem

Halcom Dashboard adalah aplikasi web internal untuk proyek, request BOQ / RFQ / PO, dan pemantauan SLA: Sales → SOA (BOQ) → Purchasing (RFQ dan PO), dengan akses baca untuk Finance dan Management.

Alamat produksihttps://halcom-dashboard.site (www. dialihkan ke alamat tanpa www)
ServerSatu Hostinger KVM VPS, Ubuntu 26.04 LTS (x86_64). Paket: [CEK PAKET VPS DI hPanel]
Containerdb (PostgreSQL 18.6), migrate (menjalankan migrasi sekali tiap deploy), app (Next.js, Node.js 24), caddy (HTTPS otomatis)
Database utamaPostgreSQL di container db pada VPS, volume halcom-dashboard_postgres_data
Salinan cadanganDump harian di volume /backups (VPS) dan salinan malam ke database Neon (layanan PostgreSQL terkelola)
KodeGitHub, organisasi halcom-solutions, repository halcom-dashboard [CEK: repo pernah dipindah dari akun pribadi; GitHub mengalihkan alamat lama]
DeployGitHub Actions Deploy to Hostinger, otomatis saat ada push ke main, menunggu persetujuan reviewer

Alur sebuah rilis

  1. Developer membuat branch dari development, lalu pull request ke development. CI menjalankan lint, typecheck, tes unit, tes integrasi, dan build.
  2. Saat siap rilis, development di-merge ke main.
  3. Workflow deploy berjalan dan menunggu persetujuan di environment production.
  4. Setelah disetujui: kode dikirim ke VPS lewat SSH, image dibangun di VPS, database di-dump, migrasi dijalankan, app dimulai ulang, lalu /api/health dicek. Bila tidak sehat, image lama dipasang lagi (migrasi tidak dibatalkan).

Struktur kode

  • src/domain: aturan murni (izin, status request, SLA, metrik). src/server: use case dan query database. src/features dan src/app: tampilan (Next.js App Router).
  • prisma/schema.prisma dan prisma/migrations: skema database. Migrasi hanya ditambah, tidak pernah diubah setelah masuk main.
  • deploy/: semua berkas untuk VPS (compose, Caddyfile, skrip deploy, backup, SLA, sinkron Neon).
  • tests/unit, tests/integration, tests/e2e: Vitest dan Playwright.
Jangan pernah di-commit: .env apa pun, folder prisma/data/ (data customer asli dari ekspor sales dan tracker RFQ), folder backups/, dan DEV_ACCOUNTS.md. Ketiganya sudah ada di .gitignore.

Jaringan dan keamanan

  • Firewall hanya membuka 22 (SSH), 80, dan 443. Cek: ufw status. [CEK]
  • Kunci host SSH VPS dipin di secret VPS_KNOWN_HOSTS. Bila VPS dibangun ulang, secret ini wajib diperbarui.
  • Aplikasi membatasi percobaan login (5 per email, 25 per alamat IP dalam 15 menit).

5. Operasional harian

Semua perintah dijalankan di VPS sebagai user deploy. Singkatan yang dipakai:

cd /opt/halcom
C="docker compose -p halcom-dashboard -f compose.hostinger.yaml"

Cek kondisi

$C ps
$C logs --tail 100 app
$C logs --tail 50 caddy
cat /opt/halcom/.last_good_tag

Deploy versi baru

  1. Merge ke main (atau Actions → Deploy to Hostinger → Run workflow dengan ref tertentu).
  2. Reviewer menyetujui run di environment production.
  3. Pantau log run di GitHub. Baris terakhir yang benar: == Done: <tag> is live.

Rollback

  • Kode saja: jalankan workflow manual dengan ref berisi commit lama yang sehat.
  • Migrasi bermasalah: migrasi tidak dibatalkan otomatis. Pulihkan dump dari predeploy/ (lihat Restore), lalu deploy commit lama.

Backup manual

$C exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -Fc "$POSTGRES_DB"' > manual-$(date -u +%Y%m%d-%H%M).dump

Superadmin juga bisa membuat dan mengunduh backup dari halaman Backups di aplikasi.

Restore

Restore menimpa seluruh database. Buat backup manual dulu, dan hentikan app selama proses.
$C stop app
cat BERKAS.dump | $C exec -T db sh -c 'pg_restore --clean --if-exists --no-owner -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
$C up -d app

Mengubah isi .env

Container hanya membaca .env saat dibuat. Setelah mengubahnya: $C up -d app.

Peringatan SLA

Uji dengan /opt/halcom/sla-scan.sh. Hasil benar: 200 dan jumlah checked, warnings, dangers, closed. 404 berarti CRON_SECRET kosong; 401 berarti secret salah.

6. Tugas terjadwal (cron user deploy)

Zona waktu server: UTC (WIB = UTC + 7). Isi yang berlaku saat ini: [CEK DENGAN crontab -l DAN SALIN DISINI]

TugasBaris cron (yang didokumentasikan)Fungsi
Backup harian30 20 * * * /opt/halcom/backup-daily.sh >> /opt/halcom/backup.log 2>&1Dump ke volume /backups pukul 03:30 WIB. Simpan 30 hari, minimal 3 berkas terbaru.
Peringatan SLA*/30 1-11 * * 1-5 /opt/halcom/sla-scan.sh >> /opt/halcom/sla-scan.log 2>&1Tiap 30 menit, 08:00 sampai 18:00 WIB, Senin sampai Jumat.
Salinan ke Neon30 2 * * * /opt/halcom/db-sync.sh vps-to-neon >> /opt/halcom/sync/cron.log 2>&1Menimpa database Neon cadangan dengan isi VPS. Hanya berjalan bila CUTOVER_DONE ada.
Jangan pernah menjalankan db-sync.sh neon-to-vps atau cutover lagi: keduanya menimpa database VPS dengan isi Neon. Skrip menolak keduanya selama CUTOVER_DONE ada; jangan menghapus berkas itu.

Cek rutin: berkas halcom-auto-* terbaru di halaman Backups berumur kurang dari 26 jam, dan sync/cron.log tidak berisi error.

7. Pengembangan di komputer lokal

Semua berjalan di Docker; Node.js dan PostgreSQL tidak perlu dipasang di komputer. Detail lengkap ada di README.md.

git clone https://github.com/halcom-solutions/halcom-dashboard.git
cd halcom-dashboard
cp .env.example .env          # isi POSTGRES_PASSWORD dan SEED_USER_PASSWORD
docker compose up -d          # aplikasi di http://localhost:3000
docker compose run --rm app npm run db:migrate:deploy
docker compose run --rm app npm run db:seed

Pemeriksaan sebelum pull request (sama dengan CI)

docker compose run --rm app npm run lint
docker compose run --rm app npm run typecheck
docker compose run --rm app npm test
docker compose --profile test run --rm app-test npm run test:integration
docker compose --profile test run --rm e2e

Database dev memakai port 55432 di host karena 5432 sering dipakai PostgreSQL lokal. Jangan pernah menjalankan docker compose down -v: perintah itu menghapus volume database.

8. Checklist serah terima

Akses

  • Penerima bisa login ke hPanel Hostinger dengan 2FA aktif.
  • Penerima menjadi owner atau admin repository di organisasi halcom-solutions, dan reviewer environment production.
  • Kunci SSH publik penerima ditambahkan ke /home/deploy/.ssh/authorized_keys dan ke user admin; login berhasil.
  • Penerima bisa login ke Neon dan ke aplikasi sebagai Superadmin.
  • Akses registrar dan DNS domain sudah dipindahkan atau dibagikan.

Rotasi kredensial (setelah akses penerima berfungsi)

  • Ganti kata sandi hPanel, Neon, dan akun Superadmin aplikasi.
  • Hapus kunci SSH penyerah dari authorized_keys (user deploy dan admin).
  • Buat kunci CI baru (ssh-keygen -t ed25519 -f halcom_ci -N "" -C "github-actions-deploy"), ganti baris lama di authorized_keys, perbarui secret VPS_SSH_KEY, lalu hapus berkas kunci dari komputer.
  • Ganti CRON_SECRET di .env (openssl rand -hex 24), lalu $C up -d app dan uji sla-scan.sh.
  • Ganti kata sandi database Neon dan perbarui neon.env.
  • Cabut token GitHub pribadi penyerah yang pernah dipakai untuk repository ini, dan keluarkan penyerah dari organisasi bila sudah tidak terlibat.
  • Kata sandi PostgreSQL di VPS (POSTGRES_PASSWORD) hanya berlaku saat volume pertama kali dibuat. Mengganti nilainya di .env saja tidak mengubah database; ubah juga dengan ALTER USER di dalam container db sebelum memperbarui .env. [OPSIONAL]

Uji fungsi setelah rotasi

  • Deploy manual satu kali dari main berhasil sampai == Done.
  • /opt/halcom/backup-daily.sh berhasil dan berkasnya tampil di halaman Backups.
  • /opt/halcom/sla-scan.sh mengembalikan 200.
  • /opt/halcom/db-sync.sh vps-to-neon berhasil.

9. Hal yang belum selesai dan risiko yang diketahui

  • Backup harian ada di server yang sama dengan database. Salinan di luar server hanya Neon dan unduhan manual. Disarankan mengunduh backup berkala ke penyimpanan terenkripsi.
  • Rollback tidak membatalkan migrasi. Pemulihan migrasi bermasalah memakai dump predeploy/.
  • Image produksi tidak memuat skrip seperti db:bootstrap-superadmin. Database baru harus diisi dari dump.
  • Belum ada Content Security Policy (butuh pengaturan nonce di Next.js), lihat deployment/SECURITY_CHECKLIST.md.
  • Satu environment saja (tanpa staging). Uji di lokal sebelum merge ke main.
  • Pertanyaan bisnis yang masih terbuka tercatat di docs/requirements/OPEN_QUESTIONS.md.
